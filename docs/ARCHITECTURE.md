# KajiBalance 設計書

## 1. 技術スタック

### Phase 1（MVP） — No-code / Low-code

| レイヤー | 技術 | 理由 |
|---|---|---|
| フロントエンド | Glide (PWA) | スプレッドシートベースで高速開発。コード不要。iOS/Android両対応 |
| バックエンド | Google Sheets + Glide Tables | サーバーレス。初期は無料枠で運用可能 |
| 認証 | Glide Auth (メール/Google連携) | 夫婦アカウント連携に必要な最低限の認証 |
| プッシュ通知 | Glide Push Notifications | タスクリマインダー |
| ストレージ | Google Drive連携 | 画像添付（オプション） |

### Phase 2（移行先候補）

| レイヤー | 技術 | 理由 |
|---|---|---|
| フロントエンド | Flutter | 本格的なUI/UXが必要になったら移行。単一コードベースでiOS/Android対応 |
| バックエンド | Firebase (Firestore + Auth + Cloud Functions) | リアルタイム同期・認証・サーバーレス |
| ストレージ | Firebase Storage | レシピ画像等 |
| 分析 | Firebase Analytics | ユーザー行動分析 |

### Phase 3（LLM拡張時追加）

| 機能 | 技術 |
|---|---|
| LLM API | Gemini 1.5 Flash（低コスト・日本語良好） |
| 画像認識 | Google Cloud Vision API（冷蔵庫写真→食材） |
| 音声認識 | Web Speech API or Whisper（ローカル可） |

## 3. 負担スコア設計（LLM不使用のポイント制）

### 事前定義テーブル（約100タスク）

各タスクに以下を固定値で持つ：
- `physical_score` (1〜10)：身体的負担（動く・力を使う・時間がかかる）
- `mental_score` (1〜10)：精神的負担（考える・忘れないように管理・決断する）

| タスク名 | カテゴリ | physical | mental | 頻度デフォルト |
|---|---|---|---|---|
| 夕飯の献立を考える | 料理 | 1 | 9 | 毎日 |
| 夕飯を作る | 料理 | 7 | 4 | 毎日 |
| 食器を洗う | 料理 | 6 | 1 | 毎日 |
| 食材の買い出し | 買い物 | 5 | 4 | 週2 |
| 洗濯（干す） | 掃除 | 4 | 2 | 週2 |
| 洗濯（たたむ） | 掃除 | 3 | 1 | 週2 |
| 部屋の掃除機 | 掃除 | 5 | 2 | 週1 |
| 保育園の準備 | 育児 | 1 | 7 | 毎日 |
| 子どもの歯磨き | 育児 | 3 | 4 | 毎日 |
| 学校行事の確認 | 育児 | 1 | 6 | 不定期 |
| ゴミ出し | 掃除 | 3 | 2 | 週2 |
| 風呂掃除 | 掃除 | 5 | 1 | 週2 |
| トイレ掃除 | 掃除 | 4 | 1 | 週1 |
| 薬の管理 | 手続き | 1 | 6 | 毎日 |
| 郵便物の処理 | 手続き | 1 | 4 | 週1 |
| ペットの餌やり | ペット | 2 | 3 | 毎日 |
| ペットの散歩 | ペット | 6 | 2 | 毎日 |
| (...) 約100件 | - | - | - | - |

### 負担率計算式

```
個人の合計負担 = SUM(担当タスクの physical_score) + SUM(担当タスクの mental_score)
総負担 = ユーザーA合計 + ユーザーB合計
負担率(%) = (個人合計 / 総負担) × 100
```

### アラート条件（定型文表示）

| 条件 | 表示メッセージ |
|---|---|
| Aの負担率 > 65% | 「今週は○○さんの負担が65%を超えています。来週は△△さんが夕飯担当を増やしてみませんか？」 |
| Aのメンタル負担のみ > 70% | 「今週の頭を使う家事（献立/予定管理）が○○さんに偏っています。分担を見直しましょう」 |
| 両方 > 60% | 「今週はお二人とも忙しかったようです。外食やミールキットを活用する週にしてみては？」 |
| 感謝ポイント < 3かつ負担不均衡 | 「感謝の気持ちを伝えると、負担感が軽減されることがあります。今日は『ありがとう』を送ってみましょう」 |

## 4. データフロー

```
ユーザー操作
    ↓
Glide Frontend
    ↓
Google Sheets / Glide Tables（データストア）
    ↓
Glideの自動集計機能 → グラフ描画
条件分岐機能 → アラート表示
プッシュ通知機能 → リマインダー送信
```

### Phase 2以降（Firebase移行時）

```
[ユーザー]
    ↓
[Flutter App] ←→ [Firestore] (リアルタイム同期)
    ↓               ↓
[Auth: Firebase Auth]  [Cloud Functions: 集計・通知]
    ↓
[Firebase Analytics: 行動分析]
```
